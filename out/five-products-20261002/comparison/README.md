# rclean：同模型、同输入的测试方案对照

本次看到少量可执行细节的增量，尚未证明加入历史 issue 后整体优于直接读 PRD。扫描根替换、恢复冲突、断管等主要风险，两组都已经提出。下列判断是对生成文本和所给测试源码的有界人工比较；没有执行产品用例，也没有做盲评或统计显著性分析。

## 对照条件

- [A：直接读 PRD](prd-only.md) · [JSON](prd-only.json)
- [B：加入历史 issue 与 PR 证据](with-issues.md) · [JSON](with-issues.json)
- 两组均使用 Codex CLI 0.160.0、`gpt-6.1-sol`、同一份 rclean README、同一组 8 个需求主题及同版本的 5 个测试源码文件。
- 两组使用相同提示词及 CLI 设置，各进行一次新的方案生成；提示词优先要求 8–12 条、最多 24 条。两组均未提供先前草稿，也不允许工具调用。
- 唯一输入差别是 `sources`：A 为空，B 为优化流程检索、提炼的 12 条 issue 及其中已抓取的有界 PR 证据。需求只保留 ID、标题和 PRD 引文，未把检索匹配或相关性说明泄漏给 A。
- 输入哈希、提示词哈希、模型及控制项见 [controls.json](controls.json)。产品和测试源码快照见 [输入清单](../inputs/manifest.json)。

## 结果

| 项目 | A：PRD-only | B：加入历史案例 |
|---|---:|---:|
| 草稿用例数 | 12 | 12 |
| 模型判断为所给文件中未检出 | 6 | 6 |
| 模型判断为部分覆盖 | 6 | 6 |
| 本次方案调用输入 token | 46,326 | 131,084 |
| 本次方案调用输出 token | 6,878 | 7,510 |
| 本次方案调用耗时 | 256.6 秒 | 289.5 秒 |

覆盖分类只是模型对这 5 个文件的判断，不是完整仓库的覆盖率，也不证明有 12 个新增测试。B 的本次方案调用输入量约为 A 的 2.83 倍；表中尚未计入 B 前置的需求检索、issue 提炼和 PR 获取成本，不据此换算价格。

| 场景 | 对照证据 | 判断 |
|---|---|---|
| 祖先目录或扫描根替换成链接 | A-TC008 与 B-TC008 都写出具体夹具、预演和实际清理检查 | 不能把它算作本次 issue 库独有的发现；A 还包含根变成普通文件的变体 |
| 混合恢复、目标冲突和失败后继续 | A-TC009 与 B-TC009 的前置条件和主要断言一致 | 历史材料没有带来新的主要故障机制 |
| 多个子项目的忽略规则 | A-TC010 已覆盖重包含与 CLI 排除；B-TC010 增加项目名称交换、按角色归一化以及不匹配 glob 对照 | 值得保留的小边界；没有复制历史产品未在目标 PRD 中声明的多根参数接口 |
| 候选过滤不能吞掉扫描告警 | A-TC011 检查尺寸过滤；B-TC011 同时检查年龄过滤 | 有具体边界细化，尚未执行，也未证明整个仓库没有对应测试 |
| 断管保留已有非零退出状态 | A-TC012 已要求保留失败状态；B-TC012 将其具体化为 `free` 不足时的退出码 3，并提到 Unix 信号状态 | 是更明确的执行示例，不宜再算成一个全新风险 |
| home、tmp、system 和显式路径的入口隔离 | A-TC002 有独立用例；B 将不少相同内容列在 R1 覆盖缺口 | 加入材料也改变了优先级；B 没有在所有重要维度上优于 A |

其他主要对应关系为 A-TC003/B-TC002（free）、A-TC004/B-TC003（stamp）、A-TC005/B-TC004（交互确认）、A-TC006/B-TC006（Docker 只读报告）。B 将部分规则与保护边界拆成不同用例，不能仅凭拆分后的条数计增量。

## 证据与局限

两组均通过应用的来源 ID、需求引文和测试源码引文校验。历史引用仍需人工判断适用性：PR 时间线的最近交叉引用包含 fork 和包管理器更新，关联不等于修复。B 的正文也保留了这些边界，没有把其他产品的修复或测试运行结果冒充成 rclean 的证据。

这次只有一个产品、每组一次新生成，不能据此估计总体胜率。它支持继续把 issue-lens 用作带出处的测试思路补充和源码对照工具；尚不支持声称它可以独立生成更完整的验收方案，或可以省掉人工审查与实际执行。
